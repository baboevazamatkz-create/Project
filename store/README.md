# Публикация в Google Play

Всё, что нужно для выхода Solidus в Play, и порядок, в котором это делается.
Со стороны кода готово всё; шаги, которые может сделать только человек с
доступом к аккаунту, отмечены **ВЫ**.

## Что лежит в этой папке

| Файл | Что это |
| --- | --- |
| `listing-ru.md` | название, описания, «что нового» — готовые к вставке |
| `data-safety.md` | ответы на три анкеты консоли |
| `graphics/play-icon-512.png` | значок 512×512 |
| `graphics/feature-graphic.png` | баннер 1024×500 |

Графика генерируется и не рисуется руками:

```bash
python3 tool/generate_store_graphics.py
```

Политика конфиденциальности — `web/privacy.html`, публикуется вместе с
сайтом на `.../Project/privacy.html`.

---

## Сначала — одно решение, которое нельзя отменить

**Идентификатор приложения сейчас:**

```
com.baboevazamatkz.expense_tracker
```

Он навсегда. Google привязывает к нему каждую установку: сменить его после
первой загрузки нельзя — другой идентификатор будет другим приложением, с
чистого листа и без возможности обновить тех, кто поставил старое. Он же
виден в адресе страницы приложения:

```
play.google.com/store/apps/details?id=com.baboevazamatkz.expense_tracker
```

То есть ваш логин будет в публичном адресе — ровно то, от чего вы хотели
уйти в адресе сайта. Сменить его можно **только сейчас**, до первой
загрузки. Скажем, на `kz.solidus.app`.

Это не одна строка: идентификатор прошит в `google-services.json`, поэтому
в консоли Firebase придётся добавить новое Android-приложение с новым
именем пакета, скачать новый `google-services.json`, и вместе с ним
переедут пути исходников виджета и названия его широковещательных действий.
Работы примерно на полчаса, из них ваших — пять минут в консоли Firebase.

**Решите до шага 4.** Если оставляем как есть — ничего делать не нужно.

## 1. ВЫ: аккаунт разработчика

https://play.google.com/console/signup — 25 долларов, разово.

Подтверждение личности занимает от пары часов до нескольких дней:
понадобится удостоверение личности, а для личного аккаунта — ещё и адрес.
Начните с этого, дальше всё быстрее.

**Личный аккаунт против организации.** У личных аккаунтов, заведённых после
ноября 2023 года, есть дополнительное требование: прежде чем открыть
публикацию, нужно провести закрытое тестирование — **не менее 12 тестировщиков,
непрерывно в течение 14 дней**. Тестировщики приглашаются по почте
(подойдут знакомые с Android). У аккаунтов организации такого требования
нет, но организацию нужно подтверждать документами (D-U-N-S).

Google время от времени меняет эти правила, поэтому точную формулировку
смотрите в самой консоли, в разделе закрытого тестирования.

## 2. ВЫ: создать приложение в консоли

**Все приложения → Создать приложение.**

- Название: `Solidus — общий бюджет`
- Язык по умолчанию: русский
- Тип: приложение
- Бесплатное
- Поставьте обе галочки в декларациях

## 3. ВЫ: подписание приложений Google (Play App Signing)

При первой загрузке консоль предложит включить Play App Signing —
соглашайтесь, это обязательно для новых приложений. Как это работает:
ключ, которым CI подписывает сборку, становится «ключом загрузки», а Google
хранит собственный ключ подписи и подписывает им то, что уходит на
телефоны. Потеря ключа загрузки перестаёт быть катастрофой — его можно
заменить.

Ключ загрузки уже настроен в GitHub Actions: секреты `KEYSTORE_BASE64` и
`KEYSTORE_PASSWORD` заданы, сборки подписываются им, и его отпечаток
печатается в журнале каждой сборки (`SHA-256 digest`). **Сам файл
хранилища ключей сохраните в надёжном месте** — он существует только у вас
и в секретах репозитория.

## 4. Собрать бандл

Уже собирается на каждый push в `main`. Свежий файл — `Solidus.aab` в
последнем релизе:

https://github.com/baboevazamatkz-create/Project/releases/latest

Это `.aab`, а не `.apk`: Play принимает только его, зато собирает из него
для каждого телефона отдельную сборку — скачивание выходит примерно втрое
меньше универсального APK. Код версии равен номеру сборки и растёт сам, а
Play отвергает загрузку, чей код версии не больше всех предыдущих.

Если понадобится собрать вручную:

```bash
flutter build appbundle --release \
  --build-number=<число больше предыдущего> \
  --dart-define=SCAN_ENDPOINT=https://solidus-scan.<имя>.workers.dev
```

## 5. ВЫ: закрытое тестирование

**Тестирование → Закрытое тестирование → Создать выпуск.**

Загрузите `Solidus.aab`, в «Что нового» вставьте текст из `listing-ru.md`.
Добавьте список тестировщиков по адресам почты и разошлите им ссылку.

Проверьте на настоящем телефоне до того, как отправлять на проверку:
- сканер (эта сборка ужата R8 — то, что раньше не проверялось);
- виджет на домашнем экране;
- вход во второй бюджет по коду.

## 6. ВЫ: заполнить карточку

**Основная информация о приложении** — тексты из `listing-ru.md`, значок и
баннер из `graphics/`.

**Скриншоты — единственное, что нельзя сделать за вас.** Play требует не
меньше двух, берёт до восьми; снимайте на телефоне, портретная ориентация,
не меньше 1080 точек по короткой стороне. Стоит показать:

1. Главный экран со списком записей и карточкой сумм
2. Шторку сканера с разобранной выпиской — это главное отличие
3. Статистику с диаграммой и лимитами
4. Виджет на домашнем экране
5. Шторку добавления расхода
6. Тёмную тему

Порядок важен: первые два скриншота видны в поиске, остальные — только
тем, кто открыл карточку.

**Анкеты** — по `data-safety.md`: безопасность данных, возрастной рейтинг,
контент приложения.

## 7. ВЫ: на проверку

Когда закрытое тестирование отработает положенный срок, откроется
публикация. **Производство → Создать выпуск** → тот же бандл → отправить.

Первая проверка обычно занимает от нескольких дней до недели. Чаще всего
возвращают из-за анкеты безопасности данных, не совпавшей с реальностью, —
поэтому она расписана подробно.

## Дальше

Каждый push в `main` кладёт новый `Solidus.aab` в релиз с новым кодом
версии. Обновление в Play — это загрузить его в выпуск и написать, что
изменилось. Номер версии (`1.0.0`) живёт в `pubspec.yaml` и меняется
руками, когда есть о чём сказать.
